## Phase 2. Anchor window

### Design

A modeless window, `gui/anchor_window.py`, owns the whole picking session. The Align step's
Go button opens it. The docked Align panel keeps the reference, the shared table, Delete
selected points, Start alignment over and More alignment options (James asked for these

`MainWindow` (`start_add_anchor`, `_show_anchor_run`, `_finish_anchor_*`, `_advance_anchor_run`,
`skip_anchor_run`) into the window, so it is not duplicated. The main 2D view no longer takes
anchor clicks.

The window has three pages in a `QStackedWidget`.

**Page 1, Phase check.** Headline: "Check the phase of every run before anchoring." Below it,
one sentence: "Anchors record where a peak sits inside its modulation. Changing the phase
afterwards moves every peak in t2 and makes these anchors wrong." Then a table of runs:
name, phase (s), method (`RunEntry.phase_method`), confidence, a small thumbnail of the
folded TIC with the period line, and a "Phase checked" tick box. "Open Fold and phase"
jumps to that step. "Continue to anchoring" is enabled only when every run to be aligned
is ticked. Store the tick as `RunEntry.phase_checked`, saved in project JSON, cleared by any
phase or period change to that run.

**Page 2, Pick anchors.**
- Header, large and bold (about 1.4 × base): "Sample 3 of 8: `<run name>`", with a coloured
  role badge, REFERENCE or SAMPLE. Below: "Anchor P2. Click the same peak you chose on the
  reference."
- A progress strip of one chip per run for the current anchor: done, skipped, current,
  pending.
- A requirement box that updates live:
  "Anchors complete on every sample: 2. Needed: 1 for a shift, 4 for a stretch, 7 for a
  curve (automatic choice). Recommended: 4 to 6 spread from early to late t1."
  Take the numbers from `core.align.AUTO_MIN` and `FIT_MIN`; do not copy them. Add a coverage
  bar showing the t1 span covered by the reference anchors, and warn when every anchor
  lies within one third of the run.
- The image: a light pyqtgraph pane (reuse `views/compare._ImagePane` or factor a shared base)
  showing the current run's folded image for the chosen signal (TIC or one ion, with an ion
  box in the window). On sample runs, draw a ghost cross where the anchor sits on the
  reference and the refinement search box around it. Build images in jobs with
  `latest_key`; cache per (run, signal, layer identity).
- Buttons: Skip this peak in this run; Back one run; Finish picking (Esc); and the primary
  button **Anchor**.

**Page 3, Check the result.** After Anchor:
- For each non-reference run, side-by-side panes with linked zoom: **Before** (reference in
  magenta, run in green, no transform, absolute coordinates) and **After** (run resampled with
  the fitted transform). A Blink toggle alternates reference and aligned run in the After pane.
- A table, one row per run: transform kind, anchors used, median anchor offset before
  (t1 s, t2 ms), leave-one-out error after (t1 s, t2 ms), image similarity before and after,
  and a status: OK, Worse after alignment, Not monotonic, Too few anchors.
- **Accept alignment** applies everything as one undoable `EditAlignment`. **Back to anchors**
  returns to page 2 with all clicks kept.

### State changes

Today every click refits that run's transform (`AlignState.add_anchor` → `_recompute`), which
also invalidates any blank-subtracted background through
`Project._alignment_changed_under_blank`. Split clicked points from applied transforms:

- `AlignState.points` stays the editable, autosaved, undoable record of clicks (unchanged
  schema), so a crash loses nothing.
- New `AlignState.applied_points` is the snapshot that transforms are fitted from. Only
  Anchor/Accept updates it. `transforms`, `aligned_runs()`, `image_for()` and blank mapping read

  transforms, and connect blank-layer invalidation to `appliedChanged` only.
- `has_pending_changes()` is true when `points != applied_points`; the panel and window show
  "Anchors changed since the last Anchor".
- Project JSON gains `applied_points`. Older projects without it load with
  `applied_points = points`, so their alignment is unchanged.
- Record each run's phase in `AlignState.phase_at_anchor[run]` when Anchor is accepted. On
  `foldChanged`, a run whose phase differs is listed as stale with "Phase changed after
  anchoring; pick again or refine". Do not convert positions silently.
- Undo/redo of Accept restores both `points` and `applied_points`.

## Phase 3. NIST library: parsing, retention indices and search (core)

### Answer to James's question

The user does not need to enter column dimensions or the temperature program. A
temperature-programmed retention index is defined relative to n-alkanes run on the same
method, which cancels most of the effect of length, diameter, film and ramp. What the tool
does need:

1. **An n-alkane ladder** for each run, or for a ladder run on the same method and day, from
   the existing ⛓️ tool. Without one, the matcher falls back to spectrum only and says so.
2. **The first-dimension stationary-phase class**, one drop-down: standard non-polar
   (100% dimethylpolysiloxane), semi-standard non-polar (5% phenyl), or standard polar (wax).
   Literature RIs for the same compound differ by hundreds of units between these classes.

Column details and the oven program are optional fields recorded in provenance only. By
default the matcher uses NIST records with program type Ramp or Complex and data type
"Linear RI" or "Normal alkane RI", because GC×GC is always temperature programmed. Isothermal
records and "Lee RI" (a PAH-based scale) are excluded by default; both are settings.

### What is in the files (checked 20 October)

| File | Records | Use |
|---|---|---|
| `mainlib.sdf` | 212,961 EI spectra; 108,401 with CAS; 197,301 with `ESTIMATED KOVATS RI` and `RI ESTIMATION ERROR` | Main library |
| `replib.sdf` | 30,932 replicate EI spectra; 29,284 with estimated RI | Extra spectra of the same compounds |
| `nist_ri.sdf` | 346,757 experimental RI records. Column class: 113,379 standard non-polar, 149,090 semi-standard non-polar, 84,243 standard polar. Data type: 155,748 "Normal alkane RI", 111,778 "Linear RI", 73,379 "Kovats RI", 5,852 "Lee RI". Program type: Ramp, Isothermal or Complex. 79,443 carry a NISTNO | Experimental RIs |
| `nist_msms*.SDF` | MS/MS spectra | Not used (not EI) |

Format notes: each record is a MOL block, then `>  <FIELD>` lines followed by values and a
blank line, ended by `$$$$`. The number of spaces between `>` and `<` varies (`> <CASNO>` occurs).
Lines end in CRLF. Peaks are `mz abundance` pairs, one per line, abundance scaled to 9999.
`nist_ri.sdf` has many records per compound (one per publication and column), linked to
spectra by CAS number, NISTNO where present, or name.

**Licence.** The NIST library is licensed to James. Never commit NIST files, parsed caches,
extracts or real spectra to the repository, and never ship them in a wheel or executable.
Tests use hand-written miniature SDF files with invented spectra. Real-library tests are
opt-in through `PYGCGC_NIST_SDF` and the `real_data` marker.

### Modules

**`core/nist_sdf.py`** (new). A streaming parser, plain-English module docstring first.
- `iter_sdf_records(path, fields=None)` yields `dict[str, str]` per record, skipping the MOL
  block; tolerant of spacing, CRLF and stray bytes (`encoding="latin-1"`). Parse peaks
  by splitting all numbers and pairing them, so one-pair-per-line and several-pairs-per-line
  both work.
- `read_ei_library(paths, progress=None, cancel=None) -> CompactLibrary` for mainlib and
  replib.
- `read_ri_records(path, ...) -> RIRecords`, columnar arrays: CAS, NISTNO, normalised name,
  RI, column class, active phase, data type, program type.

**`CompactLibrary`** (in `core/identify.py`, beside `Library`). Columnar: `names`, `formula`,
`mw`, `cas`, `nistno`, `source` (main/rep), `ri_est`, `ri_est_err`, and one CSR matrix of
float32 intensities over unit m/z. No `LibraryEntry` object per spectrum: 244,000 Python
objects with their own arrays would be slow and large. `entry(i)` builds a `LibraryEntry` on
demand for display, promotion and in-house export, so existing callers keep working.

**Cache.** `%LOCALAPPDATA%\PyGCGC\libraries\<key>\` holding `spectra.npz` (CSR arrays) and
`meta.npz`. Key: hash of each source file's path, size and modification time, plus a
`PARSER_VERSION` constant. First import runs as a cancellable job with progress; later loads
should take seconds. Record the measured first-parse and cached-load times in the handover.
This cache is separate from the results cache; nothing here feeds `CODE_FINGERPRINT`.

**RI table** (`core/identify.py`). `build_ri_table(records, column_class,
data_types=("Linear RI", "Normal alkane RI"), program_types=("Ramp", "Complex")) -> RITable`
with, per compound key, the median RI, a robust
spread `1.4826 × MAD`, and the number of records. Link to library spectra by CAS, then
NISTNO, then normalised name (lower case, whitespace and punctuation collapsed). Report how
many library entries received an experimental RI by each route.

### Retention index of a peak

`RI = 100 × AlkaneSeries.carbon_of(t1)` as now (`identify.retention_index`). Add its uncertainty:

```
sigma_query = 100 × sigma_t1 / (t1 of the next alkane − t1 of the previous alkane)
```

with `sigma_t1 = 0.25 × modulation period` for fitted components and `period / sqrt(12)` for
legacy blobs (both settings). Flag RIs outside the ladder's carbon range as extrapolated.

Ladder source, in order: the run's own ladder; otherwise a ladder run chosen in the matcher
window, through the alignment transform when both runs are aligned, otherwise by identical
t1 (flagged "ladder borrowed from `<run>`").

Library RI and its uncertainty: the experimental median for the chosen phase class with
`sigma_lib = max(1.4826 × MAD, 5)`, or 15 when only one record exists; otherwise NIST's estimated
RI with `sigma_lib` from its `RI ESTIMATION ERROR` field (flagged "estimated RI only"). The
estimate is a group-contribution method; check which phase class it represents in NIST's
documentation before using it for a polar column, and disable it there if it does not apply.

Total: `sigma = sqrt(sigma_query² + sigma_lib² + sigma_sys²)`, with `sigma_sys = 15` covering the
systematic difference between a GC×GC first dimension and one-dimensional literature
columns (provisional, D2). `z = (RI_measured − RI_library) / sigma`.

### Spectral score

- Restrict both spectra to the acquired m/z range of the run (library ions outside it are
  removed before normalising) and to the same excluded ions (user exclusions such as
  column-bleed ions; none by default).
- Weighted vectors `w = intensity^0.6 × mz^3` (Stein and Scott, 1994; the existing settings).
- Match factor `MF = 999 × cos²(w_query, w_library)`; reverse match factor the same over the
  library's non-zero ions only. Label these "dot-product match factor"; they resemble NIST MS
  Search values but are not identical (NIST's composite adds a peak-ratio term), so do not
  quote NIST thresholds as equivalent.
- Use full-ion component spectra (`peaktable.respectrum_components`), not
  `Component.spectrum`, which covers only the ~30 ions of the fitting window and often lacks
  the molecular ion. `identify_components` currently uses the window spectrum; change it, and
  keep a test that shows the difference on a synthetic component whose molecular ion was
  outside the window.

### How spectrum and RI combine

RI acts as a gate, spectrum ranks. Candidates with `abs(z) <= 3` are ranked by MF. Candidates
outside the gate are listed separately, demoted and flagged; they are never silently dropped.
Without a usable RI the ranking is spectrum only and flagged. This is easier to explain and
audit than a weighted sum. The existing MSP `search` keeps its current scoring and defaults.

### Speed

Per query: candidates = (RI window of ±3σ_max on the precomputed sorted RI array, plus every
entry without any RI) ∩ (entries sharing at least one of the query's top 5 ions, via an
inverted index ion → entries built once at load). Score them with one sparse row-slice
product `W[candidates] @ q`. Batch the target-decoy competition over the whole run as now.
Collapse replicate spectra and duplicate names to the best spectrum per compound (CAS, else
normalised name) before ranking. Target: a 2,000-component run against the full library in
under 30 s on this machine; measure and report.

Decoys: keep `generate_decoys`, but build them lazily for the candidate rows only, with a seed
derived from the entry index, so results are reproducible and memory stays bounded.

### Confidence and uncertainty flags

Per peak, a level (provisional thresholds, D2):

| Level | Rule |
|---|---|
| Confident | MF ≥ 850, experimental RI with abs(z) ≤ 2, no close runner-up, q ≤ 0.05 |
| Probable | MF ≥ 750 and abs(z) ≤ 3, or Confident apart from an estimated-only RI |
| Tentative | MF ≥ 650 |
| Unknown | otherwise; the best candidate is still shown |

Flags, each with a short sentence for the tooltip and the export:

| Code | Meaning |
|---|---|
| `RI_MISSING` | no ladder, so spectrum only |
| `RI_ESTIMATED` | library RI is NIST's estimate, not a measurement |
| `RI_EXTRAPOLATED` | peak lies outside the ladder's carbon range |
| `RI_BORROWED` | ladder taken from another run |
| `RI_TENSION` | 2 < abs(z) ≤ 3 |
| `RI_CONFLICT` | best spectral match fails the RI gate and no candidate passes it |
| `ISOMER_AMBIGUOUS` | a runner-up with the same formula within 30 MF and inside the RI gate |
| `CLOSE_RUNNER_UP` | a different compound within 30 MF inside the RI gate |
| `FEW_IONS` | fewer than 5 ions above 1% of base peak |
| `COELUTION` | the component shares its fit or is unresolved (`ComponentPeaks.co_elution`) |
| `HIGH_FDR` | q-value above 0.05 |
| `CLASS_DISAGREES` | the 🧬 class, when present, conflicts with the formula (for example an alkane class on a formula containing O or N) |

Keep the Schymanski mapping honest: Confident and Probable correspond to level 2a or 2b, the
rest to level 3. Nothing reaches level 1 without a co-injected standard.

## Phase 5. Peak-level sample subtraction

### Method (plain English for the module docstring)

Pixel-by-pixel blank subtraction subtracts noise from noise. Fitted peaks average over many
pixels, so subtracting a blank's fitted peaks from a sample's fitted peaks is far less
noisy. For every peak in the chosen run (the "blank"), find the same peak in each other run:
close in position (through the alignment where both runs are aligned) and with a similar
full-ion spectrum. Subtract the blank peak's volume times the chosen factor from the
sample peak's volume, never going below zero. Peaks with no blank partner are untouched.

### Core: `core/peak_blank.py`

```
@dataclass(frozen=True)
class PeakBlankSettings:
    blank_run: str = ""
    factor: float = 1.0
    max_dt1_modulations: float = 1.5
    max_dt2_s: float = 0.10
    min_cosine: float = 0.90
    significance_ratio: float = 3.0     # flag only (D5)
```

- `match_blank_peaks(sample_peaks, blank_peaks, settings, to_blank=None)`: one-to-one
  assignment with `scipy.optimize.linear_sum_assignment`, cost = normalised distance plus
  (1 − cosine), infeasible pairs excluded. `to_blank` maps sample coordinates into the
  blank's (`core.align.blank_mapping`).
- `subtract_blank_peaks(...) -> list[PeakBlankRow]`: per sample peak, matched blank component
  id, cosine, distance, blank volume, removed = min(factor × blank volume, sample volume),
  corrected volume, fraction removed, corrected spectrum (scaled by corrected / original
  volume), status (`removed` when corrected is zero, `reduced`, `untouched`), and the flag
  `below_significance` when sample volume < `significance_ratio` × factor × blank volume.
- `suggest_factor(rows) -> (median, iqr)` of sample/blank volume ratios over matched peaks:
  shown to the user as guidance, never applied automatically.

Matching uses full-ion spectra from the provider (phase 4). Runs at another electron energy
are excluded. The blank run itself is left unchanged.

### GUI

A new sub-step under Assign, "Subtract a run's peaks", placed after library search in the
Assign choices and before Quantify in the workflow. Settings: blank run, factor (with the
suggested median and IQR beside it and a histogram of ratios), the three matching
tolerances under More options. Go runs every run as a cancellable job.

Results: a per-run summary (peaks matched, removed, reduced; share of fitted signal removed);
a table per run with the columns above; on the 2D view, outlines coloured by status
(removed, reduced, untouched) when the step is open. Optional view, phase 5.4: the sample
image minus the factor times the blank's fitted model image (`model_on_frame` of the blank's
components, resampled through the alignment), labelled as a model-based view.

Settings live in a small `PeakBlankState` (settings, results, stale flag), saved with the
project; results are recomputed. Settings changes are undoable snapshots. Results go stale
when components, alignment or the blank run change. The matcher table (phase 4) shows
corrected volume and fraction removed when a result exists. Quantification is unchanged
(D3).
